# 跨 Client 组合角色并按角色归属披露

管理员需要用一次角色分配为任职授予一组可跨应用复用的角色。组合沿用现有角色身份与任职、岗位、组织分配，
由完整管理员维护包含关系。与限制同一 Client 内组合相比，跨 Client 组合可以直接表达跨应用职责，代价是一次关系编辑
可能改变多个应用及 IAM Admin 的授权。将组合作为持续生效的授予关系，也让已有分配随组合调整而更新。

## 授予与披露

新建角色时分别选择基本或组合形态、应用或全局归属，形态创建后固定，存量角色归为基本角色。只有显式创建的组合角色可以
作为包含方。组合可为空，删除最后一个成员后仍可分配并授予自身。基本角色和组合角色均可被包含，成员支持混合归属和多层嵌套。
保存后全部包含关系须保持无环，包括暂停、停用角色涉及的关系和并发修改的结果。对每条有效任职，从有效分配获得的角色
开始递归展开，保留组合角色自身，同一角色通过多条有效路径获得时合并为一个 Effective Role。

暂停或停用角色保留包含关系，切断经过该角色的授予路径。其他有效路径继续授予其所达角色，重新启用后恢复该路径。
所属 Client 的维护或停用继续按 [会话与 Client 通行决定](0035-unify-user-and-client-session-lifecycles.md#配置维护与凭据)
控制应用通行，跨应用继承沿角色自身的状态计算。

先对任职完整展开，再按每个结果角色的归属披露。中间角色对调用方不可见时，仍可通过它获得最终可见的角色。
OIDC UserInfo、Custom SSO 和 Internal 用户详情与搜索沿用现有响应结构，在角色集合中平铺调用方可见的本应用角色和全局角色。
Internal 过滤与响应使用同一可见集合。本决定扩展 [ADR-0048](0048-model-global-roles-without-client-ownership.md) 的授予范围，
角色的可见范围继续由各自归属和适用的披露配置决定。

继承得到的 `iam:admin` 和 `iam:hr-admin` 参与 [Admin Authorization Policy](0017-centralize-admin-role-policy-with-request-time-scope.md)。
HR 的组织范围只从实际获得该角色的任职推导。提交后的 Admin 请求按当前源事实授权，应用侧沿用
[ADR-0032](0032-consume-published-subject-facts-for-authorization.md) 的已发布事实，发布完成前可能读到旧角色集合。

## 管理与生命周期

角色详情展示直接包含的角色以及直接包含该角色的组合。完整管理员从包含方维护直接成员，可按应用、编码或名称查找角色。
未删除的暂停、停用角色也可加入，选择时展示状态并提示启用后可能影响已有分配。分配对象继续列出实际分配记录，
Admin 任职详情以平铺的有效角色列表呈现。包含关系的增删按普通保存流程提交，角色删除使用既有确认操作。

有直接分配的角色须先撤销分配。通过删除检查后，在 Role 软删除的同一事务中自动解除它作为包含方及被包含方的全部关系。

## 发布与恢复

角色或关系的变化覆盖已有分配，审计与 User Document 更新义务随源变更提交。移除关系或删除角色时须保留足够的变更前关联信息，
使后台仍可找到通过旧路径获得角色的任职。有效角色与反向影响范围沿用
[ADR-0002](0002-centralize-role-assignment-resolution.md) 的共享解析责任，文档更新与恢复沿用
[ADR-0046](0046-unify-user-and-organization-read-documents.md) 的发布流程。

开放组合写入前，实时授权和 User Document 构建、发布组件均须支持组合展开。原有文档可继续读取，随后由组合关系和角色变化
触发受影响文档更新。

实施范围与验收由 [Spec #330](https://github.com/cyy1998/shgas-iam/issues/330) 跟踪。
