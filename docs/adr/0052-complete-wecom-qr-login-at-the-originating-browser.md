# 由发起扫码的浏览器完成企业微信登录

员工电脑只访问 IAM 内网入口。手机用企业微信扫码，经 IAM 公网入口完成企业微信网页授权并确认本次登录。两个 IAM 入口通过同一条短时扫码请求关联。只有发起请求的电脑浏览器可以一次性领取结果并建立 UserSession，随后回到原 Authentication Continuation。Custom SSO 与 OIDC 沿用各自的续接和应用准入规则。

企业微信网页登录组件由浏览器访问企业微信服务，因此无法覆盖只有内网访问能力的电脑。由手机完成网页授权支持内外网使用不同域名，代价是 IAM 要维护跨设备请求状态、浏览器绑定和过期。企业微信的授权回调使用手机可访问的公网 IAM 域名，电脑在原内网入口取得会话 Cookie。

首版接入本企业的一套企业微信自建应用。既有 `/sso/third-party/wx` 继续服务现有接入方，与扫码流程复用企业微信身份查询。扫码新增的临时登录限制检查适用于跨设备流程。

## 扫码入口与确认

扫码功能由部署配置启用，首版只在内网统一登录页提供扫码入口。用户选择扫码时创建请求，有效期默认为 5 分钟，且不超过原 Authentication Continuation 的截止时间。换码使原请求失效；切换登录方式保持原请求的状态和截止时间。

手机确认页显示目标应用和电脑的粗粒度设备提示，由用户确认或取消本次登录。设备提示仅用于帮助用户辨认请求。手机取消结束该请求，电脑提示重新扫码。

多台手机可扫描同一个二维码。扫码和企业微信授权阶段允许并行，首次有效的确认或取消决定请求状态，后续操作不能覆盖结果。先确认的成员尚未绑定时，电脑只可为该成员身份继续绑定。

手机确认后，已绑定的 IAM 用户固定为本次扫码结果。后续解除绑定影响新的企微认证，已确认且仍有效的扫码请求可继续完成，账号访问与应用准入仍按现有规则检查。电脑建立 UserSession 前检查用户当前的 Temporary Login Restriction。企微授权取消或超时不会增加密码、短信登录失败次数。未绑定的员工在电脑上验证既有 IAM 凭据后立即保存绑定并继续登录。应用拒绝准入或扫码请求在绑定完成后过期时，已保存的绑定保留。

电脑只在显示扫码页时自动提交扫码登录。切回扫码页可继续有效的原请求。密码或短信登录成功时沿用该次登录续接应用，扫码请求按原期限到期。绑定时凭据错误可在原请求内重试或切换验证方式，受现有登录限制和原截止时间约束，重新发短信也不延长有效期。

完成登录的响应丢失时，先检查原授权和当前浏览器的会话。已有有效会话时续接原应用；扫码结果有效且尚未消费时可重试；扫码结果已消费而浏览器仍无有效会话时重新扫码。

## 扫码请求的状态与恢复

内外网 IAM 入口共享 Redis，以其中保存的扫码请求为权威。Redis 原子裁决首次确认或取消、到期与一次性领取。SSE 向电脑发送状态变化，重连读取当前状态。请求丢失时重新扫码，已经写入数据库的绑定保留。

## 企业微信绑定与手机号唯一性

跨设备扫码绑定的一对多演进及旧接口兼容规则见 [ADR-0053](0053-bind-wecom-identities-through-one-qr-flow.md)。

沿用用户档案已有的 `wxId` 保存企业微信成员身份。数据库分别保证手机号与 `wxId` 在所有未删除账号中唯一。停用账号保留对原值的占用，软删除后释放原值且保留历史。各写入入口去除首尾空白，空白值按未登记处理，保留 `wxId` 的大小写以及各入口已有的手机号格式要求。

首次绑定只关联现有 IAM 用户。电脑显示「验证并绑定企业微信」，接受用户名和密码，或直接输入已登记手机号及短信验证码。绑定复用登录限制、人机校验和同手机号发码冷却。专用短信验证码只对本次扫码请求和指定账号有效。两种方式分别验证账号自身的密码或实际发出的验证码。

绑定冲突时由管理员处理。`iam:admin` 通过专门的操作解除绑定，`wxId` 退出普通档案编辑。解绑后员工可重新扫码验证，已建立的 UserSession 由现有会话管理机制撤销。

本次以存量数据经规范化后已满足唯一性为前提，直接建立约束。若数据违反约束，迁移失败并保留原值，由管理员核实归属后修正。

## 审计

扫码成功沿用企业微信登录审计，记录跨设备来源。绑定和解绑分别记录操作人、目标 IAM 用户和结果。首次绑定用到的密码或短信验证方式记入绑定审计，登录审计记录企业微信扫码。
