# 在同一企业微信扫码流程中绑定多条身份

企业微信跨设备扫码沿用本企业自建应用的网页授权。IAM 使用同一个扫码入口和回调，根据企微返回的 `userid` 识别本企业成员，
或根据返回的 `openid` 识别非本企业成员。身份由授权应用所属企业的 `CorpID`、标识类型和标识值共同确定。
两种身份使用同一套确认、绑定与登录流程，用户可以用自己已有的企微身份扫码，IAM 继续用既有 IAM 账号验证绑定归属。
[企微获取访问用户身份](https://developer.work.weixin.qq.com/document/path/91023)

一个 IAM 用户可以同时绑定一个本企业成员身份和多条非本企业成员身份，每个企微身份同一时间只归一个 IAM 用户。
手机确认后，已绑定的身份可以登录其对应的 IAM 用户。添加新身份时，用户在发起扫码的电脑上通过密码或已登记手机号的短信验证码
验证目标账号，成功后追加绑定。用户加入本企业后，如果企微改为返回 `userid`，需按新身份重新验证并绑定，原 `openid` 继续保留。

## 旧接口兼容

既有 `/sso/third-party/wx` 及其 `wxId` 查询沿用现有契约和实现。存量 `wxId` 继续代表本企业成员绑定，
新增本企业成员绑定时也向旧接口提供该 `wxId`，解绑时同步清除。这样既有接入方可以继续识别最新的本企业绑定，
跨设备扫码也能支持每个 IAM 用户的多条绑定。

## 解除绑定

IAM 完整管理员可以逐条解除绑定。账号停用期间保留绑定。解绑作用于之后的企微身份查找，手机已确认且仍有效的扫码请求可以完成，
已建立的 UserSession 按现有会话管理规则处理。原浏览器领取、认证续接及应用准入继续遵循
[ADR-0052](0052-complete-wecom-qr-login-at-the-originating-browser.md)。
