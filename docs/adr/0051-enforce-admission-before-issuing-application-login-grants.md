# 签发应用登录授权前检查应用准入

IAM 在确认用户身份与目标应用后，根据目标应用的准入策略判断能否签发本次登录授权。OIDC 和 Custom SSO 共用这一判定，
包括已有 UserSession 直接授权与完成身份验证后的续接。IAM 管理后台沿用自身的管理授权。

准入只作用于新授权。在创建或续期 ClientSession、签发 Code 前检查，未通过时保留已有的 IAM 登录与应用会话。
已经签发的 Code、Token 和既有会话继续遵循各自的有效期与撤销规则。这允许管理员调整准入条件而不打断现有应用会话，
也意味着收紧策略后，已登录用户仍可继续使用尚有效的会话。

## 策略配置与事实时效

每个业务应用保存一份准入策略，默认关闭。关闭时跳过准入判定，保留已保存的条件；可先保存条件，开启时必须已有合法的非空表达式。
策略属于一次授权取得的 Client 配置。沿用 [ADR-0021](0021-bind-protocol-runtime-cache-consistency-to-snapshot-acquisition.md) 的观察边界，
保存并传播成功后，后续获取配置的授权使用新策略。已取得配置的在途授权可继续，传播失败时旧策略可能继续生效，管理员按现有配置恢复流程处理。

按合法已发布 User Document 的公开字段和目标应用的角色范围判断，包含该应用的有效 Client Role 与有效 Global Role，
与应用的对外披露选择独立。复用目录 Filter DSL 的精确比较、布尔逻辑与集合元素作用域，
包括可空字段上的原子比较为假、外层 `not` 可使它为真。编辑器提示这种空值行为。

组织、岗位和角色的编码条件按保存的值精确比较。对象改编码后，已保存的条件继续使用原值；如果原编码之后出现在其他对象的文档中，
该对象也会命中原条件。编辑器标出找不到的编码，由管理员显式修订条件。已有条件仍按正常布尔逻辑求值，包括取反。

复用已发布文档可让准入与目录使用同一套事实和条件语义，代价是源资料或角色变更后，合法旧文档仍可能允许新的授权，
重建延迟没有固定上限。合法文档不可得或无法可靠判断时，本次授权暂时不可用，可稍后重试。账号可访问性继续独立检查。
[User Document 与发布决定](0046-unify-user-and-organization-read-documents.md) · [Subject Access 决定](0029-check-subject-access-once-per-business-operation.md)

## 管理权限与记录

完整管理员在应用管理通过可视化条件组编辑、保存和启停策略，也可以选择单个用户试算当前编辑的表达式。
试算使用与实际授权相同的文档事实范围和条件语义，仅返回匹配、不匹配或暂时无法判断，无需保存策略，也不建立应用会话。

保存和启停写入管理审计。实际准入拒绝写入结构化运行日志，记录目标应用、结果和请求追踪标识。审计与日志均省略条件值和用户属性。

## 用户看到的拒绝结果

明确不匹配时，Custom SSO 直接跳转到 IAM 的无权限页。OIDC 按原响应模式向已验证回调返回 `access_denied` 和适用的 `state`，
交互式流程通过 `error_uri` 提供同一个 IAM 页面地址，由接入方带用户前往。`prompt=none` 仅返回协议错误，省略页面地址。
页面显示目标应用名称及联系管理员的提示，省略具体规则和用户属性，无自动重登。
[OIDC 错误响应规范](https://openid.net/specs/openid-connect-core-1_0.html#AuthError)
