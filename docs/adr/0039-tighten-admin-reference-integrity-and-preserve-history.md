# 收紧管理写入约束并保留可读历史

管理端审查发现用户删除会遗留有效委托引用、合法软删除会破坏责任历史读取，以及标识输入和应用删除缺少必要约束。维护者于 2026-09-18 经 Q1–Q14 确认以下领域目标和范围，并在 Q15 确认整体定稿：开放关系阻止删除，被允许保留的结束历史继续可读；账号停用与任职结束分别表达各自生命周期。

## 已确认的决定

- **Q1 / Q2：用户状态与新任职。** User Disable 保持可恢复；未删除 User 处于 Disable 时禁止新增 Employment，Enable 和 Pause 仍允许。恢复账号不会重开已结束任职，返聘建立新任职。该规则收紧此前 HR 可为任意未删除 User 创建 Employment 的口径，对完整管理员与 HR 使用相同业务前提。
- **Q3：删除用户的委托阻断。** 用户作为委托人或受托人涉及任何未删除、未结束的 Privilege Delegation 时拒绝删除；Pause 和尚未进入业务期间的委托同样阻断。是否结束由委托生命周期表达，不以当前是否生效代替；先处理委托再删除用户，不由删除命令隐式结束委托。
- **Q4：软删除后的责任历史。** Ended Organization Responsibility Assignment 继续读取关联 User、Organization 和 Position 保留的当前名称，并展示其软删除状态；不增加任命发生时的名称快照。Open 责任的引用完整性要求不因历史展示而放宽。
- **Q5 / Q11 / Q12：标识和名称输入规范化。** 用户名、组织编码和岗位编码先去除首尾空白，再检查非空、长度及既有唯一性；三个标识的长度上限统一为 64 字符。姓名、组织名称和岗位名称也先去除首尾空白，再检查非空及各自已有长度限制，名称不新增唯一要求。标识不新增大小写转换，既有唯一性继续覆盖软删除记录。规则覆盖全部在线创建、修改入口，包括 Internal 联系人注册及组织创建、修改；查询保持现有精确匹配语义，密码不套用标识规范化规则。
- **Q6：删除应用的角色阻断。** Client 存在任何未删除 Role 时拒绝删除，不区分 Role 状态。先按现行规则处理角色分配和 Role，再删除 Client，不以删除应用隐式级联清理授权关系。
- **Q7：已有任职与状态文案。** Disable 用户同时禁止新增 Employment 和 Transfer；转岗被拒绝时不结束旧任职。已有 Open Employment 仍可依原有授权与生命周期规则修改说明、暂停、恢复、结束以及设置或清除主任职；账号停用不自动结束任职，整体结束任职继续使用 User Resignation。用户 Disable 的管理端文案由“结束”改为“停用”。
- **Q8：HR 返聘流程。** Disable 且没有 Open Employment 的用户，先由完整管理员恢复为 Pause，再由 HR 在其管理范围内新建任职；用户重新满足 HR User Status Administration 的条件后，由 HR 启用账号。不凭已结束任职赋予 HR 额外的账号恢复权限。

## 本次修复沿用的权限展示口径

Admin 用户和任职详情的权限集合只包含由当前有效角色派生、且权限本身为 Enable 并未软删除的权限，与正式用户档案的过滤口径一致。现有遗漏状态和软删除条件的详情查询按此修复；不扩展 Admin 的角色授权策略，也不增加历史权限展示模式。

## 取舍与既有决定的关系

删除阻断保留显式业务处理顺序，代价是删除前需要处理关联关系；不会把单一对象删除扩展为难以察觉的委托或授权撤销。责任历史使用保留的当前名称，能够容纳正常软删除，但不承诺重建任意历史时刻的名称或状态。

本决定收紧 [ADR-0011](0011-model-employment-as-an-immutable-tenure-lifecycle.md) 的任职创建前提，并明确 [ADR-0014](0014-model-organization-responsibility-as-employment-bound-fact.md) 的 Ended 管理历史与 Open 完整性检查各自的适用范围。[ADR-0020](0020-provide-fail-closed-privilege-delegation-resolution.md) 对异常委托解析失败关闭的规则继续保留；用户删除门禁补充 [ADR-0026 历史原文](https://github.com/cyy1998/shgas-iam/blob/73315e4cef6f96dd79b29e18f74d68af30e559ec/docs/adr/0026-serialize-privilege-delegation-writes-by-delegator.md) 当时未覆盖的引用生命周期治理。

本轮沿用 [ADR-0025](0025-align-admin-mutation-results-with-committed-facts.md) 的同对象写入规则，以及既有跨对象预检的乐观边界。Q10 已明确不为本次门禁增加跨对象锁定、提高隔离级别或协调重试；因此本决定不承诺创建与删除、任职创建与账号停用并发时的强一致保证。输入规范化不改变 [User Profile Search Condition](../../CONTEXT.md) 已有的精确查询语义。

## 已明确的范围限制与后续事项

- **Q9：委托管理入口另行处理。** 本次交付用户删除的委托阻断，不新增 Admin 关联委托列表或结束入口；已有委托继续通过现行 Internal API 处理，管理端入口留待后续任务。
- **Q10：并发保证不扩展。** 本次实现顺序操作下的业务门禁，继续遵守现行事务和同对象写入规则，不将跨对象并发保证纳入范围。
- **Q13：不做存量标识治理。** 维护者明确线上不存在本次讨论的存量空白或规范化冲突；据此不增加存量盘点、改名、合并、数据修复工具或迁移。这是本次范围判断的业务前提，不是已执行数据库审计的结论。
- **Q14：不处理已删除应用的遗留角色。** 本次不开展这类存量盘点或清理，也不因该假设扩大当前有效角色过滤规则；新增的 Client 删除门禁用于约束后续合法操作。
