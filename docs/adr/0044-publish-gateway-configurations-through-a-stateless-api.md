# 通过独立无状态 API 发布网关配置

现有 Gateway 使用本地 CLI 发布 YAML，第三方应用无法通过统一 API 自行提交配置。
决定将该能力迁入 `apps/gateway/`，提供独立的无状态配置发布服务，第三方应用和 IAM 自身统一使用 API；
调用方保管配置，服务不新增期望配置数据库、历史版本或后台发布任务，并移除原有直接发布 CLI。
本页是已接受的目标决策；具体契约见 [Gateway 配置 API 契约](../features/gateway/gateway-configuration-api.md)，
实施与验收见 [Spec #253](https://github.com/cyy1998/shgas-iam/issues/253)。

## 取舍

首版沿用现有 YAML 的表达能力和按资源调用 APISIX Admin API 的方式，配置归属以 IAM Client 表达，
通过调用方提交的 Internal API Client Secret 验证其是否匹配 scope 中的 Client code；
不增加域名或路径分配审批及细粒度权限模型。独立端口允许在 IAM 网关路由尚未建立时完成首次配置。
选择直接执行请求而非持久期望状态与后台协调，目的是把本次范围限制在已有配置发布能力的 API 化。

认证只读查询 IAM 当前 Client 记录，校验未删除、Enable 状态及 Internal Secret，不使用 SSO Secret 或既有缓存。
这增加了对 IAM 数据库的读取依赖，但不新增配置存储或凭据副本，也避免依赖尚未注册的 IAM HTTP 路由。
每次请求重新认证，已获准的在途发布仍继续完成；首次发布 IAM 配置前需准备 code 与其 scope 一致的 Client。
复用 Internal 凭据的前提是收紧现有公开 Client 状态响应中的凭据字段；scope 匹配无法弥补凭据可被公开取得的缺口。

发布失败后执行一次同步补偿，恢复本次尝试修改的资源，不自动重试。
接受配置可能短暂部分生效、补偿自身可能失败，以及结果未知或进程崩溃后需要人工恢复的代价；
仅在能够确认恢复完成时报告“已回滚”，不承诺原子发布或所有故障下必然恢复。
无持久化恢复记录意味着重启不能自动重建本次发布前态，也不能恢复上一次请求的执行结果。

本实例内的发布与恢复串行执行，恢复失败或未知后等待人工处理。
人工核对并修复 APISIX 后，通过重启服务解除内存中的发布阻断，不增加专用解锁接口；重启不代替恢复核验。
调用方断连不取消已开始的操作，服务继续完成原发布及必要补偿，不另起或重放发布；
未收到响应的调用方按结果未知处理，不自动重发。
同一集群统一写入口属于部署约定，不在代码中强制唯一实例，也不引入分布式锁。
因此该串行控制与回滚保证不覆盖其他实例或外部写者同时修改配置的情况。
以后需要多写者协调、崩溃自动恢复或原子切换时，应重新决策相应的一致性与状态所有权。
