# 用户搜索

内部应用可按用户资料、有效任职、组织、岗位、角色和组织责任组合条件查找用户。
所有有效 Internal Client 使用相同公开字段，默认返回主体标识和用户名，也可选择需要的公开字段。角色过滤与返回都使用本应用的有效角色和任职上的有效全局角色，独立于 SSO 配置；没有可见角色的有效任职在选择角色时仍保留空角色列表。

## 查询与结果

- 范围包含所有未删除用户，包括启用、暂停和禁用账号。需要限定状态时，调用方自行筛选。
- 任职条件只匹配有效任职，暂停或已结束的任职不满足条件。
- 可选择用户资料、有效任职及其组织、岗位、责任与可见角色。选择父字段可取得完整公开子树。字段选择保留所有任职、数组次序、空数组和空值，公开结构排除数据库主键、历史任职和审计字段。
- 可省略筛选条件浏览目录，按公开根级资料组合排序；未指定时按内部 ID 升序。默认关闭分页，一次最多匹配 500 人，响应包含列表、准确数量和为空的分页元数据。
- 显式开启分页可浏览超过 500 人的集合，默认第一页、每页 50 人，每页最多 500 人。可跳转指定页，越过末页返回空列表和真实总数；排序作用于全部匹配资料后再取页。
- 单次列表与总数来自同一快照，不同翻页请求可能观察到资料更新，因此不承诺整轮浏览没有重复或漏看。
- 委托单独查询，不参与用户搜索。Internal 用户详情返回完整公开文档，与同版本、同 Client 上下文下选择全部根字段的搜索单项一致；Admin 保留实时管理模型。

## 条件组合

条件可按“同时满足”“满足任一”“排除”组合，也可以限定同一条任职或同一个组织路径节点。

例如，“在 A 部门任职并担任经理”若放在同一个任职条件中，要求同一条任职同时满足；分成两个独立任职条件，则允许不同任职分别满足。
组织子树条件包含所选组织自身。值按精确值比较，不做模糊匹配，也不自动忽略大小写或首尾空格。

空值有特定规则：手机号为空的人也会满足“手机号不等于某个值”。详细表达方式见[过滤语法](../../guides/search.md#组合条件)。

## 更新延迟与异常

搜索读取后台发布的资料，源数据变化后可能暂时仍返回旧值。尚未发布、缺失或版本不匹配的资料会被跳过；没有当前匹配资料时返回空列表。

条件或分页参数非法、过于复杂，或关闭分页时结果超过 500 人，整次查询被拒绝，不截断返回。
查询超时或本次返回范围的完整资料损坏时也会失败，字段选择不能隐藏损坏。分页只完整校验本页，精确总数不表示其他页资料都已通过完整性检查。
正常返回不代表所有源用户都已完成资料发布；完整性检查由维护流程执行。

需要委托信息时，应用再用搜索结果分批解析代办人，每次最多 100 个用户名。各批查询可能处于不同时间点。

调用方式见[搜索接入](../../guides/search.md)，数据修复见[数据维护](../../releases/data-maintenance.md)。

精确详情没有当前可读条目时返回 404，可能表示不存在、删除、尚未发布或 schema 不匹配，不证明源用户不存在。文档损坏或查询失败返回 503，不回源拼装另一份详情。
