# 组织搜索

内部应用可按组织属性和组织路径筛选组织。所有有效的内部应用都能查询完整公开字段，不按应用限制组织子树。
查询对象是组织，不支持按成员、岗位、角色或责任人反查，也不查询历史组织。

## 查询与结果

搜索包含未删除的启用、暂停和禁用组织，需要限定状态时自行筛选。
每个结果包含组织编码、名称、类型、状态、层级、虚拟或实体属性，以及从根到自身的完整路径。

- 路径保留全部祖先，包括已暂停或禁用的祖先。
- 层级从根的第 1 层起算；相对距离从目标自身的 0 起算，父级为 1。
- 可以组合组织属性、路径节点和子树条件，子树条件包含所选组织自身。
- 筛选和返回使用同一份完整文档，结果顺序和字段固定，最多 500 个组织；不支持分页或自定义排序。

组织详情、管理端搜索、组织树和选择器仍使用各自入口，不受此搜索方式替代。

## 更新延迟

各组织分别在后台更新，单份结果内部一致，但一次查询可能读到不同组织的新旧资料。
新建组织首次发布前可能搜不到；刚删除的组织也可能暂时仍出现在结果中。
祖先编码、名称或类型变化后，其全部后代的路径资料也需要更新。

构建失败时保留已有合法旧资料并重试，没有固定的更新时间保证。

## 查询失败时

条件非法、过于复杂或匹配超过 500 个组织时，整次查询被拒绝，不截断返回。
查询超时或匹配文档损坏时也会失败。

尚未发布、缺失或版本不匹配的文档会被跳过，其他匹配组织仍可返回。因此成功响应不代表源组织已全部进入搜索。
更新异常时应修复搜索文档，不要重复修改源组织来触发补偿。

条件和示例见[搜索接入](../../guides/search.md)，重建见[数据维护](../../releases/data-maintenance.md)。
