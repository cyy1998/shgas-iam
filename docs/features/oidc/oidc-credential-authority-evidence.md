## 行为证据

`subject-access-authorization.integration.test.ts` 使用真实 Provider TCP HTTP server、正式 Session/Provider composition
工厂和真实 Kernel、Subject Access Barrier、Facts cache、Token store。Client Runtime/Gate 与 account repository 使用替身；
不是完整生产配置/数据库性能观察。生产进程接线另由现有 Composition profile 配真实 PostgreSQL/Redis 验证。

新增行为矩阵覆盖根子索引遗漏后正式撤根、漏撤 UserInfo 成功及自身 Binding/Credential/anchor/Provider payload 失效拒绝；
同时验证 Code 前置根失效未消费、新授权无 Code、非目标 Client 保留、一次许可且无父/账户读取。
Token extra、Credential metadata、Binding 认证时间和主体/Session/Client 矛盾矩阵失败关闭；Binding 到期仍拒绝。

在 Kernel 完成真实根观察、尚未写 Credential 时同步暂停，先正式撤根再放行，可晚到签发并使用，期限不超过原根当前及绝对期限。
Binding 已在此前观察，暂停中删除或撤销 Binding 仍可交付在途响应，但不复活对象且后继 UserInfo 拒绝；不增加提交时对象屏障。
既有 OIDC 根/Binding 续期、Custom SSO 固定期限、Code 重放/PKCE/消费冲突、用途、版本、暂态及账号代际测试保留。

旧 Claims 单元测试中“根认证时间变化则拒绝”的保护迁为 Token/Credential/Binding 认证时间一致性；去掉的根 resolver fixture
不再承担当前访问要求。签发和协议生命周期替身补齐可信 Code 认证时间，未删除其原精确撤销与非目标断言。

## 采样口径

before 生产代码为 `847469e16e8d500eeea5ec104e44712aee25f197`；在修改生产父读取之前，先添加未提交的观测测试并实际运行。
命令为 `pnpm --filter @iam/oidc-provider test:integration:redis subject-access-authorization -t 'observes successful UserInfo' --disableConsoleIntercept`。
同一正常 `/oidc/me` 入口一次 warmup 后串行五次 HTTP 200；不把授权、兑换、失败分支或其他测试计入窗口。

ioredis writer `sendCommand` 调用前及完成时记录单调时间，RTT 包含调度、传输、Redis 执行与客户端处理，不能称为纯网络时延。
按开始时间排序，将相交的在途区间合并为一波；开始不早于前一波结束才增加波数。MONITOR 用 `source=lua` 区分内部调用；
HTTP 完成后由独立连接发送 ECHO marker 并等待监控确认，marker 与连接初始化不计入样本。输出只有命令名、来源类别、时间和数量，
不输出参数、key、token、主体或 marker。before 采样命令成功但默认 Vitest console interception 隐藏输出，随后带上述显式参数重新采集。

本地 Windows、Node.js 24.18.0、ioredis 5.11.1、Vitest 4.1.10、Docker Server 27.5.1、Redis 8.8.0；任务独占容器
`c261b22a30c2abd50288c8474453e60e240437d909c546153f6d21b79d30eef4`，动态宿主端口 38746，OIDC 采样 DB 1。
Kernel namespace 每例独立；资源 owner 串行、独立 DB，未以开发或生产资源作为性能样本。

before 与 after 使用同一容器、同一命令和同一采样块；前者执行于本地 23:23:50，后者执行于 23:40:39（Asia/Shanghai）。
两次均包含真实 Provider HTTP 往返，但下表累计 RTT 仅求和 Redis 命令区间，不计 HTTP、JIT、密钥生成或 fixture 初始化耗时。
