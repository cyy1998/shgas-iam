# 网关配置发布

应用通过网关配置服务提交路由、上游等配置。调用方保管源配置，网关保存实际生效的配置。
首次发布可以直接连接配置服务，无需先配置 IAM 的网关路由。

## 使用条件

调用方须持有对应应用的有效内部接口凭据，应用处于启用状态。IAM 自身的配置也按相同规则认证。
该认证不提供完整的多租户隔离；域名、路径、插件使用范围和发布审批仍需另行管理。

## 发布流程

1. **校验**：检查配置格式和必要字段，修正错误。
2. **预览差异**：查看准备创建、修改、删除或忽略的资源。
3. **发布**：系统重新读取当前配置并计算差异，再执行变更。可以先试运行，只查看计划。
4. **检查业务访问**：配置写入完成后，仍需确认实际路由和业务访问。

删除默认关闭。主动开启后，仅删除本应用、本环境中由该配置来源管理、且已从源配置移除的资源；其他来源的资源保留。
待删除的消费者若仍有独立子凭据，须先由负责方处理这些凭据。

预览不会锁定后续发布计划。重复提交也不总是无变化，例如证书私钥的表示差异可能再次触发更新。

## 失败与恢复

发布失败后停止后续写入，并尝试恢复本次涉及的资源。发布和恢复期间可能短暂出现新旧配置并存，已处理的业务请求无法撤销。
无法确认恢复结果时，服务暂停后续发布，等待人工处理。

调用方超时或断连后，原发布可能继续执行。未收到响应时不要自动重发，应等在途操作结束，再核对实际配置。
服务没有持久任务或历史结果查询，进程退出后也无法自动找回本次恢复进度。

单个服务实例同一时刻只执行一次发布，忙时直接拒绝新发布。部署须避免其他实例或外部工具同时写入同一网关，否则回滚结果无法保证。
人工恢复后才能重启开放发布，重启本身不代表配置已修复。

调用和配置示例见[网关接入](../../guides/gateway.md)，部署与恢复步骤见[网关运维手册](../../releases/apisix-gateway-release.md)。
