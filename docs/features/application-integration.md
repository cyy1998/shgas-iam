# 应用接入

接入应用通过 IAM 验证用户身份并取得获准共享的用户信息。每个应用选择 OIDC 或 Custom SSO。
已有有效 IAM 登录时，用户通常可直接继续，完成后返回发起请求的应用。内部应用还可使用凭据发布本应用的网关配置。

## 应用配置

完整管理员管理应用的登录协议、回调地址、用户信息范围和接入凭据；HR 管理员无此权限。
业务身份、角色归属和内部接口凭据分别管理。

### 配置和启停

启用登录须具备所选协议的有效配置。停用会保留配置，删除登录配置会关闭登录并保留应用本身。

- Custom SSO 可选择业务回调或托管回调，两种方式的回调配置不同。
- OIDC 按应用类型配置回调和允许提供的用户信息。
- 配置地址须通过校验；业务系统只能使用允许的回调。
- 保存配置或切换协议通常保留已有凭据；需要更换凭据时单独执行轮换。

编辑、启停、切换协议和轮换凭据无需先进入维护状态，也不会直接终止既有会话。
后续访问仍按新配置判断；正在执行的请求可能使用此前已取得的配置。某些登录兑换失败会影响原应用会话，见[单点登录](#单点登录)。

### 查看和轮换凭据

SSO Secret 生成或轮换后由管理员主动读取，审计提交确认后才显示。普通 SSO 配置详情仅提供该凭据的元数据。
SSO Secret 只在当前页面临时展示，刷新或离开后清除。读取响应丢失时可以重读，无需再次轮换。

登录凭据和内部接口凭据用途不同，不应混用或交给浏览器代码保存。
读取后如果另一个管理员完成了轮换，刚取得的值可能已失效。

### 删除应用

删除前须处理未删除角色，以及尚未结束的委托等依赖。暂停或禁用的角色仍会阻止删除；已结束委托和已删除角色的历史不阻止删除。
通过检查后删除应用，并终止相关应用会话。

应用已删除但会话清理未完成时，可按提示重试剩余处理。删除结果不确定时应先查询当前状态，不能根据报错直接认定删除未生效。

### 配置保存后的异常

配置可能已经保存，但尚未同步到实际使用处；此时旧配置或旧凭据仍可能被接受。
页面会保留修复提示，刷新详情或重新读取凭据都不能替代修复。不要自动重复保存或轮换。

## 单点登录

### 选择接入方式

| 方式                | 适用情况                           | 应用负责什么                                   |
| ------------------- | ---------------------------------- | ---------------------------------------------- |
| Custom SSO 业务回调 | 业务后端接收登录结果并管理本地会话 | 接收回调、兑换登录结果、保存本地会话和处理退出 |
| Custom SSO 托管回调 | 由 IAM 在业务域写入登录 Cookie     | 部署回调代理，接入用户信息或网关鉴权           |
| OIDC                | 使用标准 OIDC 客户端接入           | 按登记的入口和回调完成授权、验证身份与退出     |

OA、微信可信登录可先完成 IAM 身份验证，再继续目标应用的登录。发起身份验证的系统和目标应用可以不同。

### 登录流程与限制

1. 用户从应用发起登录，IAM 校验应用和返回地址。
2. 已有有效登录时继续授权；否则完成身份验证，再继续原请求。
3. 应用接收一次性登录结果，按所选方式建立访问状态，并取得获准提供的用户信息。

内外网入口可能对应不同 OIDC 身份，接入应用须固定入口，不能混用。
当前不支持在已有有效 IAM 登录下再次弹出认证流程；要求重新认证的 OIDC 请求会被拒绝。
登录结果只能兑换一次。兑换失败或结果不确定时，返回应用重新发起，不能重复兑换；部分失败还可能使原应用会话失效。

## 用户信息共享

IAM 根据应用的配置，向接入应用提供用户身份、联系方式、有效任职和可见的角色信息。
用户的稳定身份标识始终提供，其余资料按允许范围返回。业务权限由应用根据这些信息自行判断。

### 提供哪些信息

- 应用按自己的披露配置获得本应用的有效角色和任职上的有效全局角色。
- 组合角色可通过其他应用所属的成员继续授予角色。IAM 展开每条任职的有效角色后，按结果角色各自的归属披露，
  并在任职和用户的角色列表中分别去重。
- 任职信息与角色信息用途不同；取得任职资料不代表获得业务权限。
- 调整披露范围后，后续用户信息查询使用新范围，包括使用既有登录凭据发起的查询。
- 已签发的离线身份凭证内容固定，不会随配置或用户资料修改而重写。

任职、组织责任目标与目录文档使用相同的组织基础结构和完整路径。路径同时提供层级与距目标的距离，
各协议继续按应用的披露配置选择资料与角色；已有有效登录凭据沿用原绑定、期限和一次消费规则。

字段和协议差异见[Custom SSO 接入指南](../guides/custom-sso.md#用户信息与-gateway-鉴权)与[OIDC 接入指南](../guides/oidc.md#tokenscope-与当前披露)。

### 更新延迟与失败

资料和角色由后台更新，查询可能返回较早的数据。重建持续失败时，已有合法数据仍可能被使用，因此角色撤权没有固定传播期限。
账号禁用、会话退出等访问检查单独执行，不会因为还有旧资料就放行。

必要资料暂时无法取得时，本次交付失败，调用方可稍后重试用户信息查询；已经消费的一次性登录结果不会恢复。
接入应用负责刷新自己的数据副本，IAM 发布新资料不会自动更新第三方副本。

实现与读取规则见[主体投影](../../packages/client-subject-projection/README.md#已发布-facts-与披露)，重建和恢复见[数据维护](../releases/data-maintenance.md)。

## 退出责任

IAM 退出会终止相应登录的后续在线访问。应用自行处理本地会话、已复制资料和离线身份凭证。

管理员操作见[应用配置与凭据](../guides/admin.md#应用配置与凭据)，应用调用见
[Custom SSO 指南](../guides/custom-sso.md)和[OIDC 指南](../guides/oidc.md)。用户认证与会话撤销见[登录与会话](login-and-session.md)。

## 网关配置发布

调用方持有源配置，网关持有生效配置。未删除且启用的应用可使用 Internal API Secret 校验、预览和发布，首次发布可直连服务。
域名、路径、插件范围和审批由部署侧管理。

- 校验与预览只读。正式发布重新读取远端状态并计算差异。默认保留已从源配置移除的资源，主动开启删除后也只处理本应用、本环境、由本配置来源管理的资源。
  待删消费者仍有独立子凭据时，发布在写入前拒绝。
- 每个实例同时只执行一次发布，同一网关保持单一写入口。失败后停止后续写入并尝试恢复已触及资源，期间可能短暂混用新旧配置，已处理请求的作用保留。
- 超时或断连时原发布可能继续。恢复失败或结果未知会阻断后续发布，核对实际配置与数据面后再解除阻断。

调用与试运行见[网关接入](../guides/gateway.md)，部署和人工恢复见[网关运维](../releases/apisix-gateway-release.md)。
