# 组织责任管理

组织责任把某项责任绑定到一段任职和一个目标组织，供管理和查询使用，本身不授予业务操作权限。
完整管理员可全局管理；HR 管理员只能管理授权范围内的责任。

## HR 的管理范围

一条责任的任职所属组织和目标组织都必须在当前 HR 范围内。两端可以分属不同的授权组织树，管理员自己也可以成为责任人。
该规则同时适用于查询、创建、暂停、恢复、结束和历史读取。

责任类型由 IAM 统一维护，管理端只读。有有效管理范围的 HR 可读取完整类型目录，但不能查看全局审计或责任操作日志。
权限按每次请求重新判断；已经授权的操作可能在撤权后完成，后续请求使用新范围。

## 创建和管理

先选择责任类型、任职和目标组织，再提交创建。任职与目标组织须启用，并满足该责任类型的名额限制。
HR 的选择列表只显示范围内候选，提交时仍会再次检查权限。

| 操作         | 结果                                     |
| ------------ | ---------------------------------------- |
| 暂停         | 暂停责任，仍占名额                       |
| 恢复         | 重新检查关联对象和名额，通过后恢复       |
| 结束         | 永久结束，不能重新打开                   |
| 合法重复操作 | 提示无需修改，保留操作意图和原有历史时间 |

责任类型、任职和目标组织创建后不可更改，也不能删除责任记录。
任职或关联对象发生变化时，责任还会受相应的生命周期规则约束。

## 查询和历史

HR 可从责任管理页面，以及组织、任职和用户详情进入。列表和详情只显示当前可管理记录，已结束记录只读。
历史显示关联对象的当前名称和删除状态；对象已软删除不一定影响完整管理员查看历史，但可能使 HR 失去原有范围。
关联对象真正缺失或组织路径损坏时，查询会失败。

## 名额占用与失败

范围外的责任也可能占用名额或阻止组织操作。HR 看不到这些记录的详情，只会收到安全提示；当前列表没有可处理记录时，应联系完整管理员。

越界操作会被拒绝，非法状态转换不会被当成成功。页面按当前权限和状态显示操作，写入后刷新。
