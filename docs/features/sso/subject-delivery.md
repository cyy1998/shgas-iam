# 用户信息共享

IAM 根据应用的配置，向接入应用提供用户身份、联系方式、有效任职和该应用的角色信息。
用户的稳定身份标识始终提供，其余资料按允许范围返回。业务权限由应用根据这些信息自行判断。

## 提供哪些信息

- 各应用使用自己的披露配置，不能借此获取其他应用的角色。
- 任职信息与角色信息用途不同；取得任职资料不代表获得业务权限。
- 调整披露范围后，后续用户信息查询使用新范围，包括使用既有登录凭据发起的查询。
- 已签发的离线身份凭证内容固定，不会随配置或用户资料修改而重写。

字段和协议差异见[Custom SSO 接入指南](../../guides/custom-sso.md#用户信息与-gateway-鉴权)与[OIDC 接入指南](../../guides/oidc.md#tokenscope-与当前披露)。

## 更新延迟与失败

资料和角色由后台更新，查询可能返回较早的数据。重建持续失败时，已有合法数据仍可能被使用，因此角色撤权没有固定传播期限。
账号禁用、会话退出等访问检查单独执行，不会因为还有旧资料就放行。

必要资料暂时无法取得时，本次交付失败，调用方可稍后重试用户信息查询；已经消费的一次性登录结果不会恢复。
接入应用负责刷新自己的数据副本，IAM 发布新资料不会自动更新第三方副本。

实现与读取规则见[主体投影](../../architecture/backend-architecture.md#client-subject-projection)，重建和恢复见[数据维护](../../releases/data-maintenance.md)。
