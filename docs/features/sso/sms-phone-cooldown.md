## 实施前的基线行为

前端发送成功后执行页面内 60 秒倒计时。后端 `MobileService.sendCode` 校验手机号后调用短信供应商，
再保存按用途区分的验证码；该基线没有手机号发送冷却。Gateway 的 IP 限流和可配置的人机验证均不能替代手机号限制。

## 已确认的目标

1. Q1：所有短信验证码发送入口按同一手机号共享 60 秒冷却，包括登录、找回密码和绑定手机号。
   切换用途、IP 或浏览器不能绕过。
2. Q2：通过手机号、人机验证等发送前校验后，在调用供应商前占用发送资格并开始计时。
   一旦尝试发送，无论成功、失败或超时，均保留冷却；发送前校验失败不占用。
3. Q3：冷却固定为 60 秒，始终启用，不增加环境变量开关。
4. Q4：多个后端实例共享 Redis 中的冷却状态，以原子操作取得发送资格。
   无法检查或取得资格时拒绝发送，并向调用方提示暂时不可用。
5. Q5：手机号冷却拒绝返回 HTTP 429 和剩余等待秒数，前端根据服务端剩余时间恢复倒计时。
   刷新页面后再次尝试发送也应获得服务端剩余等待时间。

6. Q6：供应商发送失败或超时后，前端同时展示失败提示与剩余冷却倒计时。
   Redis 不可用、无法确认剩余时间时，只提示暂时不可用，不虚构剩余时间。
7. Q7：冷却独立于验证码生命周期。验证码使用成功不解除冷却；被限频拒绝的请求不延长冷却，
   也不修改此前已发送的验证码。
8. Q8：验证码发送的供应商请求增加 10 秒超时，不自动重试。超时保留原冷却，
   迟到结果不得触发验证码保存等后续成功处理。取消本地等待不能保证供应商未发送或未送达短信。

## 实施边界

所有现存验证码发送入口汇聚到 `MobileService.sendCode`，冷却由该共同边界执行。
冷却使用校验后的同一手机号身份，首尾空格不得产生独立额度；不把用途、用户、IP 或进程实例加入冷却身份。
普通业务短信的独立 `sendMessage` 方法不属于本次已讨论的验证码发送入口。

Redis 原子操作同时决定发送资格和受限时的剩余时间；不能先读后写，也不能退化为进程内计数。
冷却到期允许新的发送尝试，拒绝不会重新计时。冷却与按用途保存的验证码使用独立状态。

实施前 HTTP 错误链已支持 `Retry-After`，但 SSO 的 `ServiceError` 未保留该信息。
本次在 transport/service 层将服务端等待秒数转换为页面可消费的错误信息，页面据此更新倒计时。
手机号冷却拒绝与 Gateway IP 限流必须能够区分，不能将所有 HTTP 429 都解释为手机号冷却。
供应商失败仍表达发送失败，同时在可确认时携带剩余冷却时间；状态不可确认表达暂时不可用。

## 验收场景

- 同手机号跨用途、跨入口、跨后端实例并发请求，只允许一个取得发送资格并调用供应商。
- 不同手机号互不占用额度；首尾空格不能绕过同手机号限制。
- 60 秒内重复请求返回限频及剩余秒数；重复拒绝不延长原到期时间，到期后允许再次尝试。
- 手机号或人机验证等前置校验失败不占用额度；Redis 检查或占用异常时不调用供应商。
- 供应商失败、网络异常及 10 秒超时均保留冷却；无自动重试，超时后的迟到结果不保存验证码。
- 验证码消费不删除冷却；被拦截的发送不覆盖、不删除原验证码。
- 登录、找回密码、绑定手机号页面在收到冷却错误或携带剩余时间的发送失败时同步倒计时。
- 刷新页面后再次发送仍被后端限制并恢复剩余倒计时；无法确认剩余时间时显示暂时不可用。

上述内容是验收目标，不作为当前代码或部署已经满足要求的证据。

## 实现与验证记录

后端由 `MobileService.sendCode` 统一执行冷却，`createMobileCodeCooldown` 使用 Redis Lua 原子占用和读取剩余时间。
`SmsCooldownError`、`SmsSendFailedError` 经既有错误中间件输出各自业务码及 `Retry-After`；
`SmsUnavailableError` 返回 503，不提供未知的重试时间。SSO request 保留等待秒数，共享倒计时 hook
仅接受短信冷却或发送失败业务码，三个页面消费该行为。

2026-09-17 已执行 API、SSO、Contracts 的 typecheck 与 Unit，API 和 SSO 的完整 Component Integration。
真实 Redis 使用任务独占的 Redis 8.8.0 容器与随机测试 namespace，定向验证跨实例并发、跨用途及空格变体、
验证码消费后仍受限、供应商失败保留冷却、Redis 断开时零发送，以及真实 60 秒到期且拒绝不续期。
测试不调用真实短信供应商，也不代表线上部署验收。

发布需更新 API 与 SSO。旧 SSO 仍会收到后端限频错误，但只有新 SSO 会同步剩余秒数；新 SSO 对缺少
`Retry-After` 的旧 API 不虚构冷却信息。所有提供验证码发送的 API 实例升级后，跨实例限制才完整生效。
本变更无数据库迁移、环境变量或 Gateway 配置变更。
