# 登录与会话

用户通过统一登录访问 IAM 和接入应用，也可以找回密码、修改密码或退出会话。管理员可在授权范围内查看和终止会话、解除临时登录限制。

## 登录与找回密码

- 支持密码、短信验证码，以及已接入的 OA、微信登录。各方式有各自的身份校验条件。
- 登录应从目标应用发起。已有有效登录时，通常直接回到原应用；请求失效时需返回应用重新发起。
- 登录检查暂时失败时，页面提示重试，不会直接显示密码表单。找回密码页面可单独使用。
- **登录守卫与找回密码** 找回密码使用已绑定手机号。账号不存在或未绑定手机号时，统一提示无法获取号码，并停止发码和重置。
- 页面只展示脱敏手机号，但号码片段仍可能透露账号信息。

- **人机校验（Cap 与图片验证码降级）** 需要人机校验时，SSO 优先使用 Cap。Cap 无法启动、求解失败或等待超过 10 秒时，原表单的输入框下方会自动显示图片验证码。
  图片有效期为 2 分钟。答错后可以继续输入，也可以主动换图。换图会使上一张图片失效。取图和提交过快时页面会提示等待。
  答对后页面会重试原操作一次，取消时保留原表单。该流程覆盖密码登录、短信登录、发送短信验证码、找回密码时查询脱敏手机号，以及企业微信首次绑定时的凭据验证。

- **短信冷却** 短信验证码按手机号共用 60 秒冷却，登录、找回密码、绑定手机号和企业微信首次绑定共用额度，换设备或浏览器也不会重置。
  发送失败或超时仍需等待冷却结束；使用验证码不会提前解除冷却。普通业务短信不受此限制。

- **找回密码和绑定手机号的验证码** 最终提交时先校验并一次性消费验证码，再写入账号变更。找回密码的提前校验会保留验证码供最终提交。
  验证码一经消费，写入失败也需重新取码，并沿用同一手机号的发码冷却。提交结果无法确认时，先核对变更是否已生效，再决定是否重新取码。

- **密码登录凭证** 密码登录使用加密凭证。当前默认配置仍有防重放时间窗口缺口，需注意[已知限制](../releases/authentication-and-session.md#凭证时间窗口与防重放限制)。

## 企业微信跨设备扫码登录

1. **生成与确认二维码**。从内网应用进入统一登录页后，可主动选择企业微信扫码。手机经公网完成企业微信授权，看到目标应用和电脑设备提示后确认或取消。
   扫码请求最长有效 5 分钟，受原认证续接期限限制。换码会作废原请求，切换电脑端登录方式会保留仍有效的请求。
   同一码可由多台手机打开，首次有效确认或取消决定结果。取消、超时或状态丢失后，回到电脑重新扫码。
   手机确认时固定已绑定的 IAM 用户，或固定待绑定的企业微信身份。企微返回本企业成员标识时使用 `userid`，返回非本企业成员标识时使用当前企业范围内的 `openid`。
   手机只做授权和确认，登录会话由发起扫码的电脑完成。
2. **添加扫码绑定**。尚未绑定的企微身份在发起扫码的电脑上进入「验证并绑定企业微信」。可以用既有 IAM 账号和密码验证，也可以直接输入 IAM 已登记的手机号和实际收到的短信验证码。
   绑定短信只在本次扫码请求及对应的 IAM 账号和手机号上有效。输错时可在原期限内重试或切换方式，重发仍受同手机号冷却和原扫码期限约束。
   两种方式都遵循账号访问规则和临时登录限制。绑定冲突时联系管理员处理。
3. **完成绑定与后续授权**。验证成功后保存绑定，并由原电脑继续发起扫码的 Custom SSO 或 OIDC 授权。应用拒绝准入、扫码随后到期或浏览器未收到登录结果时，已保存的绑定仍可供下次扫码使用。
   绑定审计记录操作者、目标账号、结果及使用的验证方式。

一个 IAM 用户可同时绑定一个本企业成员身份和多条非本企业成员身份，每条绑定都能用于扫码登录。账号停用期间保留绑定，删除账号时释放占用。
完整管理员可以逐条解绑，手机已经确认且仍有效的请求可以按原规则完成。旧 `/sso/third-party/wx` 接口继续使用本企业成员绑定。

## 登录与应用会话

一次 IAM 登录可关联多个应用。登录期限固定，普通访问不会延长；应用会话的期限不能超过所属 IAM 登录。
退出某个应用会话不影响其他应用或其他 IAM 登录；终止 IAM 登录后，其关联应用的后续在线访问都会被拒绝。

账号禁用或删除后，新的访问会被拒绝。已经通过检查的操作仍可能完成。重新启用账号不会恢复旧会话，需要重新登录。
应用状态和接入配置也会影响访问，规则见[应用接入配置](application-integration.md#应用配置)。

## 查看和终止会话

管理员可按权限查询用户登录、应用会话和临时登录限制。本人安全操作仅限本人。
会话记录与账号当前可访问性分别判断。界面操作见[会话与登录限制](../guides/admin.md#会话与登录限制)。

- 可以终止单个应用会话、单次 IAM 登录或选定用户的一批会话。
- 管理操作保护当前登录；批量下线仍会处理当前登录关联的应用会话。
- 批量操作只处理开始时选定的记录，新建立的会话可能不在本批范围内。
- 会话列表可能不完整，显示的总数不能当作实时在线人数。查询异常时请先重试，不要基于不完整的列表扩大撤销范围。

失败或结果未知的项目会单独列出。用户确认后可重试原批次；若响应丢失且没有批次记录，先重新查询，再发起新操作。
部分失败不会恢复已经终止的会话，界面也不会自动重试。

## 修改密码与全部下线

本人通过 `POST /api/iam/auth/account/password` 保存新密码并记录审计，既有 IAM 登录和应用会话继续按各自的有效期和访问规则处理。
全部下线保留当前 IAM 登录，终止其关联应用会话及本次选中的其他会话。部分失败按[会话操作结果](#查看和终止会话)处理。
账号禁用、删除或离职后的遗留清理只处理原有登录，不应影响后来重新启用账号建立的新登录。

## 临时登录限制与异常处理

登录失败过多会暂时阻止新的认证，已有会话不受影响。页面显示自动解除时间，管理员也可按权限提前解除。
解除会同时清除当前失败历史；之后再次失败会重新计数，没有额外宽限期。

会话终止或解除限制操作可能已经生效，但审计保存失败。此时请刷新页面确认当前状态并保留修复提示，刷新成功并不代表审计记录已补齐。
IAM 不保证第三方自行保存的本地会话同时退出，接入应用须处理自己的退出和数据清理。

运维恢复见[登录与会话手册](../releases/authentication-and-session.md)。
