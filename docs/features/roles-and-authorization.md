# 角色、管理授权与审计

角色通过有效任职授予，为 IAM Admin 授权和应用访问提供角色事实。接入应用自行判断业务操作权限。

## 角色授予与可见性

- 角色归属分为 Client Role 与 Global Role，形态分为基本角色与组合角色。归属类型、形态、编码与所属应用创建后固定。
  全局角色归 IAM 统一管理并使用 `global:` 编码前缀。
- 可按任职、岗位和组织分配角色。组合角色可跨 Client 包含基本或组合角色，关系保持无环。
  有效任职从有效分配展开角色并去重。暂停或停用切断经过该角色的路径，其他有效路径继续生效。
  删除前须撤销直接分配，软删除会解除该角色的包含关系。
- 对外先展开角色，再按各结果角色的归属披露。Internal 用户目录按认证 Client 读取本应用有效角色及有效全局角色。
  Custom SSO 和 OIDC UserInfo 还应用当前披露配置。角色与资料经后台发布，接入方可能读到旧事实。

## Admin 权限与 HR 范围

- 完整管理员拥有全局管理能力。HR 范围从实际承载 `iam:hr-admin` 有效角色的任职推导，由对应一级根组织及子树组成。
  同时拥有多种管理能力时取并集。权限按请求时当前事实判断。
- HR 可读取用户及任职历史，按当前范围维护已有用户资料、组织、任职与责任。
  账号状态变更和首次离职要求目标全部开放任职在范围内。HR 可重置符合管理资格且启用的账号密码，范围外任职不影响该资格。
  转岗要求源任职与目标组织均在范围内。
  组织责任按[双端范围](directory-management.md#组织责任管理)授权。
- 应用配置和角色管理由完整管理员负责。管理界面展示服务端给出的能力与操作范围。

后台操作见[角色和组织责任](../guides/admin.md#角色和组织责任)，任职状态见[用户、组织与任职](directory-management.md)。
决定与取舍见[Admin 授权](../adr/0017-centralize-admin-role-policy-with-request-time-scope.md)、

## 审计日志

有审计权限的管理员可查询安全操作的操作者、目标、动作、结果、请求来源与脱敏摘要。HR 的组织责任管理权限独立于全局审计及责任操作日志权限。

- **记录范围**。终止会话、解除登录限制、轮换或读取凭据等操作留下审计。合法的重复操作可保留操作意图。会话审计分别统计确认终止、失败和未知结果，成功数只计确认终止。
- **查询**。可组合动作、成功或失败及目标类型。已知动作显示标准名称，未知动作保留原名。目标编码支持模糊搜索，纯数字还精确匹配目标 ID。
- **脱敏**。使用业务身份、脱敏手机号和变化摘要。密码、验证码、登录凭据、Cookie、Secret、可认证摘要、会话内部状态和原始异常均排除。
- **失败作用**。会话终止或限制解除可能先于审计提交，已生效的作用保留。“可能已生效”时须核对状态再处理后续问题。
  SSO Secret 原文仅在审计提交确认后交付。本人改密后审计或下线失败，已保存的新密码仍生效。

查询操作见[审计与日志](../guides/admin.md#审计与日志)，运行日志排障见[日志与排障](../releases/observability-system-logs.md)，
历史数据规范化见[运维入口](../releases/README.md#一次性迁移与旧版本)。
