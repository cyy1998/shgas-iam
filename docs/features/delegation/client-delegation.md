# 应用委托

委托用于在指定应用和组织范围内，为一名用户指定直接代办人。受托人使用自己的身份，角色和权限保持不变；能否办理具体业务，由接入应用判断。

## 谁能管理

| 使用者           | 可用操作                                         |
| ---------------- | ------------------------------------------------ |
| 完整管理员       | 查看、代建和管理全部应用的委托                   |
| HR 管理员        | 不具备委托管理权限                               |
| 用户本人         | 在个人设置中管理“我委托的”，只读查看“委托给我的” |
| 已认证的内部应用 | 创建、管理和解析本应用的委托                     |

应用之间的委托互相隔离，即使双方用户相同也分别管理。

## 创建委托

选择委托人、受托人、应用、组织、开始和结束时间，按需填写说明。
双方用户、应用和组织须存在、未删除且启用；不能委托给自己。允许跨部门，也不要求双方持有该应用角色。

委托无需受托人确认，可以提前安排。开始时间须早于结束时间；委托启用且处于业务期间内时才参与代办人解析。
组织范围包含所选组织及当前全部后代，后来新增的后代也会纳入。

## 修改、暂停和结束

- 创建后，双方用户、应用和组织不可更换；需要调整时先结束原委托，再创建。
- 未结束的委托可修改期间和说明，也可暂停或恢复。暂停只停止解析，仍占用原期间和组织范围。
- 自然到期不等于手动结束，到期后仍可延期；暂停的委托延期后仍暂停。
- 手动结束不可恢复；重复结束不会改写历史。委托没有删除操作，结束和到期记录仍可查询。

同一委托人在同一应用下，两条未结束委托的组织范围和期间均重叠时，拒绝创建或修改。
同组织、祖先与后代算范围重叠，时间首尾相接也算重叠；暂停或受托人相同不能豁免。不同应用互不冲突。

## 关联对象与历史

委托建立后，用户或组织暂停、禁用不会结束委托，也不改变解析结果；受托人的登录和业务权限仍需单独检查。
应用停用后不能调用内部接口，但委托记录保留。

未结束委托会阻止删除其直接绑定的双方用户、应用和所选组织，包括暂停、尚未开始和已自然到期的委托。须先显式结束，再按对象原有规则删除。
结束后的历史记录显示关联对象的当前名称与删除标记，不保存创建时名称。

## 查询结果与异常

代办人解析只查当前应用，返回零或一个直接代办人，不沿委托链继续查找。
未匹配时返回无代办人；输入用户或组织不存在、同一用户匹配多条委托、存在自委托或引用损坏时，整次查询失败，不自行选取其中一条。

写入成功后刷新列表；冲突、已结束或权限不足时先处理原因，再决定是否重试。结果不确定时先查询，避免重复写入。
调用方式见[委托接入](../../guides/delegation.md)。旧权限委托切换须按[迁移指引](../../releases/README.md#一次性迁移与旧版本)执行，已经使用新模型的环境保留现有委托。
