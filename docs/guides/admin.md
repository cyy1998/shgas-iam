# 管理后台操作

登录 IAM 管理后台后，从导航进入相应模块。系统按账号权限展示可用操作。角色和组织范围见[角色与管理授权](../features/roles-and-authorization.md)，账号与任职规则见[用户、组织与任职](../features/directory-management.md)。

## 用户、组织、岗位与任职

HR 可在管理后台打开「使用帮助」，按内置手册的截图维护已有用户资料、组织、任职和组织责任。
完整的操作步骤由[后台内置手册](../../apps/admin/src/pages/help/hr-manual-content.ts)维护。

1. 在用户管理核对姓名、工号和账号状态，再打开详情。通过任职信息核对组织、岗位和历史。
2. 在任职管理选择新增、转岗、暂停、恢复或结束。转岗时核对目标组织、岗位和新任职的主任职选项。
3. 办理离职前核对全部开放任职，操作后核实账号、任职和会话状态。删除账号前还须处理未结束委托。

## 应用配置与凭据

1. 在应用管理打开目标应用的登录配置，选择 OIDC 或 Custom SSO，填写协议对应的回调和披露范围，再启用登录。
2. OIDC Confidential 或 Custom SSO 业务兑换使用 SSO Secret。在登录配置点击「读取当前 Secret」，需要换值时先「轮换 SSO Secret」再读取。
   读取失败时可再次读取。搜索、委托、网关发布与 OA 签名使用「基础信息」页的「内部 API 凭据」所管理的通用应用密钥。
3. 删除应用前处理页面提示的角色和委托阻塞项。删除后若仍有会话清理待处理，按提示重试剩余作用。
4. 保存后若显示配置同步修复提示，按[操作结果与修复](#操作结果与修复)处理。

接入方按[应用与凭据](README.md#应用与凭据)选择相应指南。启停、删除与凭据规则见[应用接入配置](../features/application-integration.md#应用配置)。

## 角色和组织责任

- 在角色管理按应用或角色类型查找。创建时选择基本或组合形态、应用或全局归属。组合成员从包含方详情维护。
  删除前撤销直接分配，并核对受影响任职的有效角色。
- 从组织责任管理，或组织、任职、用户详情进入责任记录。创建时选择责任类型、任职和目标组织。
  可用用户条件按姓名或账号做不区分大小写的包含筛选。刷新或从详情返回列表时保留该条件，使用重置查询清除。
- 仅有 HR 管理权限时，页面隐藏审计标签页。遇到看不到详情的名额或关联阻塞时，联系完整管理员。相关边界见[组织责任管理](../features/directory-management.md#组织责任管理)。

## 应用委托

从委托管理查找本次要操作的应用和记录。创建时选择委托人、受托人、应用和组织，填写起止时间，按需补充说明。
调整固定绑定时先结束原委托，再创建新委托。暂停、结束与冲突处理见[应用委托](../features/client-delegation.md)。

## 会话与登录限制

1. 在会话管理按用户查找记录，手动刷新并展开应用会话或临时登录限制。
2. 确认目标范围后终止单个应用会话、单次 IAM 登录或一批会话。需要解除限制时核对目标及预计自动解除时间。
3. 失败或未知的目标按界面提示确认后重试原批次。响应丢失且没有原批次时，重新查询再发起新操作。
   出现可能已生效的提示时，按[操作结果与修复](#操作结果与修复)确认实际状态。

本人改密与退出规则见[登录与会话](../features/login-and-session.md)。整批运维清理或恢复见[运维手册](../releases/authentication-and-session.md)。

## 审计与日志

在审计日志按动作、成功或失败、目标类型及编码或 ID 查找记录。记录范围见[审计日志](../features/roles-and-authorization.md#审计日志)。
应用错误和 Trace 排障见[日志与排障](../releases/observability-system-logs.md)。

## 操作结果与修复

界面提示已提交、可能已生效或结果未知时，先重读详情或刷新状态，保留修复提示，根据查到的事实处理剩余作用。

- 应用配置已保存但同步未确认时，请运维人员按 [Client Snapshot 修复](../releases/authentication-and-session.md#client-snapshot-修复)恢复传播。
  详情可读或重新取得凭据只能确认当前读取结果。
- 会话终止或解除登录限制后的审计失败，先核对会话或限制的实际状态，已经生效的操作进入审计修复，未完成的业务作用按对应流程处理。
