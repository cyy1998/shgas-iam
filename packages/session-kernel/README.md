# @iam/session-kernel

Session Kernel 只拥有 UserSession 和 ClientSession，Redis 决定时间、关系、观察与撤销。Kernel 不依赖 Subject Access、协议、API Core 或 app。
协议拥有 Code、Token 与续接。认证用例校验凭据和登录限制，记录认证方式和审计，再创建根。Custom SSO 经注入的应用接口访问会话，Admin 经撤销接口操作。

## 会话与可信观察

- **会话关系与有效期**：根会话（`UserSession`）的身份、认证事实、context 与有效期创建后固定。同一根会话和同一 Client 的 `open` 操作会原子新建或复用有效应用会话（`ClientSession`），更新协议标记并单调延长其有效期（不超过所属根会话期限）。协议凭据的有效期受两类会话上限约束，正常访问或重新授权均不延长旧 Token。根会话终止后在线校验立即拒绝，已在处理中的授权仍可能落入旧根会话。
- **操作级观察与交付前重验**：观察对象绑定到对应的 factory 与当前活跃操作，不能通过复制或序列化伪造。迟到的交付前必须重新校验会话活跃性，关闭当前操作不会取消已发出的 Redis 写入。
- **跨操作独立性**：下一次操作需重新查询并建立观察；通过内部 ID 查询时，调用方仍须自行检查认证、归属与访问许可。

## 列表与撤销

- **有界列表查询**：列表仅查询有界索引，遇到损坏记录直接拒绝，跨页翻页不保证全局快照一致。
- **先捕获再撤销**：撤销操作不要求账号处于可访问状态，会先校验并完整捕获显式的目标实例 ID（已终止实例同样纳入捕获），随后严格按稳定实例身份执行撤销，不能沿动态游标边遍历边删除，也不得替换为当前占槽的新实例。
- **结果分类与不可逆终态**：结果区分已终止、已被替换、失败与未知（`unknown`）。重试仅限原批次中失败或未知的实例；若目标集合丢失，须重新查询并发起新操作。响应丢失保留 `unknown` 状态，重试遇到终态不再重复计数。终态记录保留原过期期限，索引清理失败不会回滚已达成的终态；协议产物不在 Kernel 中做二次登记，也不提供可靠后台补齐。
